Research program · live since September 2026

An agent whose identity survives model swaps.

Persistent-1 is not a chatbot, a fine-tune, or a model. It is a substrate — prose in git — that any model can execute: an identity pack, a compounding memory, a nightly consolidation daemon, and a growth suite that measures whether the agent actually got better. The agent is the reading tradition, not the reader.

The floor is its body; the repository is its mind. Nothing ships on vibes here: every capability claim carries a measured result, and every result carries a class on the honesty ladder below.

  • live: 46 daily attendant beats since Sep 2
  • runtime: HOLD — swap protocol gates release
  • tests: 29/29 green offline (11 + 18)
  • voice brain: quant verdict pending

What it is

Five components, each backed by a measured result rather than a demo:

01 · Identity pack

A prose document that defines what the agent protects, owes, and never does — independent of which model serves it. It survives tokenizer, model, and hardware changes because it is text, not weights.

02 · Memory substrate

Git-versioned markdown plus SQLite full-text search. Pages are admitted through a verification gate, never deleted — superseded with provenance. 231 memory pages and counting.

03 · Consolidation daemon

Nightly distillation of the day's learnings into causal abstractions, promoted through verification gates. The dream log records every promotion; unverified content never enters memory.

04 · Growth suite

Seeded daily task generators and property-based graders measuring operator-minutes replaced — not tokens generated. Two-channel contamination control keeps the suite honest.

05 · Swap test

The proof of identity persistence: a different model, reading the same substrate, must give the same answers about who it is. A failed swap test is a critical incident.

What happened this week

The program's status as of 2026-10-15, in the order it landed:

  1. 2026-10-15 · consolidation

    Four lineages, one canonical repository

    The live deployment lineage, the hardened code forge, recovered laptop worktrees, and the research desk merged into a single canonical repo — nothing discarded, full-fidelity snapshots preserved on the side. One mind, one history.

  2. 2026-10-15 · law

    The learning law changed: prose-anchored, multi-channel

    Directed by the CEO, ruled by the lab: Persistent-1 may learn through any channel that measurably helps — weights, latent thinking, compressed states, code — but prose stays the portable anchor, every non-prose channel must compile back to a portable form, and every channel must pass its own swap test before it counts. No eval trail, no channel.

  3. 2026-10-15 · integration

    Fast-voice substrate landed on master

    A cache-friendly prompt layout for the fast voice model: the identity pack is a byte-identical ~5 KB stable prefix, retrieved memory pages are appended last, and quarantine material is structurally excluded from every retrieval. All 29 offline tests green — re-run by hand the day this page was written.

  4. 2026-10-15 · measurement

    Swap gate pre-registered before any score

    The identity-swap gate now has its metric and floors pinned in writing before the first scoring run — down to the exact question set and a similarity floor of max(0.30, 0.90 × reference). Floors registered after a run are void by rule; this is how the scores stay worth believing.

  5. 2026-10-15 · running now

    Quantization ladder: the tiny lab has spoken

    To run the voice brain on small hardware, can a 4-bit model match a 6-bit one? At the 350M scale the lab reached a terminal verdict — generic 4-bit fails deep composition (23/32), better calibration data does not fix it (22/32), but protecting 26 attention and convolution tensors — a 9.9% size cost — restores full parity (32/32, zero anomaly counters, 93/96 vs the fp16 reference). The 2.6B voice-brain legs are staged and running now; the verdict consumes those rows, not the tiny lab's prior.

  6. 2026-10-15 · security

    Adversarial review closed, conditions bind

    An independent security review of the multi-channel design closed with four binding conditions — quarantine never enters runtime, log re-derivation is offline and treated as untrusted, identity artifacts stay encrypted least-privilege, and compilers act as gates. The latent-state learning channel stays closed until its own gate list clears.

  7. standing · operations

    Runtime HOLD — deliberately

    The deployed brain is untouched while the swap protocol runs: the live lineage is preserved branch-and-bundle, and the daily attendant keeps writing its beat — 46 beats and counting. No service change ships until the swap test and a verified rollback clear. The HOLD is the discipline, not a delay.

How results are allowed to sound

Every claim on this page sits somewhere on a ladder, and the ladder is the point. A result may only be called what it was measured to be:

  • preparedProtocol written and pre-registered. No run yet, no claim.
  • isolated-acceptedRun offline or on a benchmark. Real measurement, not yet the live stack.
  • production-accepted ← everything must earn thisRun on the live stack with a real model swap and a verified rollback path. Nothing in this program is production-accepted yet — including the integration that landed this week.

Why a landing page reads this careful: Persistent-1's product is accumulated capability, measured in operator-minutes replaced. A marketing claim it can't cash is a contamination event against its own memory. This page is written to the same standard the agent holds itself to.
